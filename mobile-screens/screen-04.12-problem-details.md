# Screen 04.12: تفاصيل المشكلة والبلاغ الميداني (Screen 10.12 - Problem Details)

## 🎯 الغرض من الشاشة ونظرة عامة (Overview & Purpose)
تُمثّل هذه الشاشة واجهة الفحص والتدخل المعمق لبلاغ أو مشكلة تشغيلية محددة (`Issue Resolution Workspace`). تفتح فوراً عند النقر على أي مشكلة من شاشة الدعم (`Screen 04.11 / 10.11`).

تُمكّن الشاشة مسؤول التوصيل من:
1. **معاينة خطورة المشكلة**: معرفة كود البوكس، المنطقة، عدد البوكسات المتأثرة، ودرجة الأولوية.
2. **فحص السائق الحالي المكلف**: الاطلاع على حالته الميدانية وبيانات مركبته مع إمكانية الاتصال المباشر به فوراً بنقرة زر.
3. **مراجعة شرح المشكلة والصور المرفقة**: قراءة تفاصيل البلاغ ورؤية صور الإثبات المرفوعة من الميدان في معرض مصغر.
4. **التحقق من بيانات الطلب والعميل**: اسم العميل، عدد الوجبات، فترة التسليم، موقع الاستلام والتسليم التفصيلي.
5. **اتخاذ القرار الحاسم**: إما تعيين سائق بديل (`Assign Replacement Driver`) فوراً في حال تعثر السائق الحالي، أو إغلاق المشكلة كـ "تم الحل" (`Mark as Resolved`).

### 2. تسجيل حل المشكلة وإغلاقها
- **الرابط (Route)**: `POST /api/v1/dispatcher/support/issues/{issueId}/resolve`
- **جسم الطلب (Request Body)**:
```json
{
  "resolutionNotes": "تم التواصل مع العميل بنجاح وتم تسليم الوجبات في موعدها"
}
```
- **الاستجابة المتوقعة (`HTTP 200 OK`)**:
```json
{
  "issueId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "resolvedAtUtc": "2026-09-22T08:45:00Z",
  "message": "تم حل المشكلة وتحديث حالة البلاغ بنجاح"
}
```

## 📱 إرشادات مطور الموبايل (Flutter / React Native Guidelines)
1. **التنقل لتعيين سائق بديل**: عند الضغط على زر `[ تعيين سائق بديل ]`، يتم فتح `Screen 04.13` مع تمرير `problemId`.
2. **معاينة الصور بكامل الشاشة**: عند النقر على أي من صور الإثبات `evidencePhotoUrls`، فتح `ImagePreviewModal` مع دعم التكبير والتصغير (Zoom & Pinch).
3. **تحديث الحالة في الشاشة السابقة**: فور تأكيد حل المشكلة أو تعيين سائق بديل، يجب إرسال إشعار للشاشة الأم (`Screen 04.11`) لتحديث القائمة والعدادات دون الحاجة لإعادة تحميل التطبيق بالكامل.
