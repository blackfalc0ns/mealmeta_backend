# Screen 05.05: قائمة ومتابعة طلبات السائق (Driver Orders List / All Deliveries & Tasks)

## 🎯 الغرض من الشاشة ونظرة عامة (Overview & Purpose)
تُمثّل هذه الشاشة **مركز قائمة المهام والطلبات الكاملة للسائق**، وهي الواجهة المخصصة للتبويب الثاني **"الطلبات" (Orders Tab 📋)** في شريط التنقل السفلي للتطبيق (`Bottom Navigation Bar`).

تتيح الشاشة للسائق:
1. **استعراض شامل لكافة الصناديق والطلبات:** كشف تفصيلي مرتب تسلسلياً حسب خط السير ومحطات التوزيع المقترحة (`Stop Sequence`).
2. **فلترة سريعة وتصنيف لحظي:** تقسيم فوري للطلبات بين (الكل، قيد التوصيل/في الطريق، تم التسليم بنجاح، تواجه مشكلة/بلاغ).
3. **بحث سريع وذكي:** إمكانية البحث الفوري عن أي طلب برقم الباركود/كود البوكس (`BX-458722`)، أو اسم العميل، أو الحي/المنطقة.
4. **إجراءات ميدانية مباشرة وسريعة:**
   - زر الاتصال الفوري بالعميل `[ 📞 ]` (عبر الاتصال المباشر أو المقنع لحماية الخصوصية).
   - زر التوجيه والملاحة الفورية `[ 🗺️ ]` يفتح تطبيق الخرائط الخارجي (Google Maps / Waze) بإحداثيات منزل العميل الدقيقة.
   - زر الانتقال لشاشة تفاصيل الطلب والمحطة (`05.04`) أو شاشة التسليم ومسح باركود الفاتورة (`07.02`).

### 1. رأس الشاشة وبيانات الرحلة (Header & Trip Banner)
- **عنوان الشاشة:** `قائمة الطلبات` بخط عريض وواضح.
- **بانر الرحلة النشطة:**
  - كود الرحلة: `TRP-48-8752`.
  - كبسولة الحالة: `[ 🟢 خارج التوصيل ]` (أو `[ 🟡 قيد الاستلام ]` إذا كانت الرحلة في مرحلة المطبخ).

### 2. شريط البحث والفلترة (Search Bar & Filter Tabs)
- **حقل البحث (Live Search Input):**
  - أيقونة عدسة `🔍` مع نص تلميحي: *"بحث بكود البوكس، اسم العميل، أو المنطقة..."*.
  - إمكانية المسح بنقرة زر `(✖️)`.
- **كبسولات الفلترة (Filter Chips):**
  - `الكل (8)`: يعرض كافة طلبات الرحلة الحالية.
  - `قيد التوصيل (2)`: يعرض الطلب النشط حالياً والطلبات التالية المتبقية.
  - `تم التسليم (5)`: يعرض الطلبات المسلمة مع توقيت تسليم كل منها.
  - `بلاغات ومشكلات (1)`: يفرز الطلبات المتعثرة (العميل لا يرد، عنوان خاطئ، طلب إعادة إسناد).

### 3. بنية كارت الطلب (Order Card Anatomy)
كل كارت يُمثّل محطة تسليم مستقلة (`TripStop`) ويحتوي على:
- **شارة الترتيب والكود:** شارة دائرية للترتيب التسلسلي مثل `2/8` بجانب كود الباركود `BX-458622`.
- **شارة الحالة (Status Badge):**
  - `[ 🟢 تم التسليم ]` (أخضر زمردي `#00B894`) مع توقيت الإنجاز.
  - `[ 🟡 قيد التوصيل الآن ]` (أصفر تحذيري `#FDCB6E`) مع تأثير نبضي خفيف (`Pulsing Glow`).
  - `[ 🟠 في الطريق للعميل ]` (برتقالي `#E17055`).
  - `[ 🔴 بلاغ مشكلة ]` (أحمر مرجاني `#D63031`) مع ذكر نوع المشكلة.
- **بيانات العميل:**
  - اسم العميل كامل ومميز.
  - زر اتصال سريع دائري `[ 📞 ]` (يفتح شيت خيارات الاتصال `08.06` المباشر أو `08.07` المقنع).
  - زر ملاحة سريع دائري `[ 🗺️ ]` (يفتح مسار الملاحة الجغرافي الخارجي).
- **تفاصيل العنوان:**
  - الحي والمنطقة، رقم القطعة، الشارع، ورقم المنزل أو العمارة.
- **بيانات الوجبات والموعد:**
  - عدد الوجبات ونوعها (`3 وجبات • غداء`).
  - نافذة التسليم المحددة (`وقت التسليم: 09:30 ص`).
- **أزرار الإجراء السريع (للطلب النشط فقط):**
  - `[ 🗺️ فتح المسار ]`: ينقل السائق مباشرة إلى شاشة الخريطة الحية وسلايدر المحطات `05.04`.
  - `[ 📦 إتمام التسليم ]`: ينقل السائق مباشرة إلى شاشة تأكيد الوصول ومسح الباركود `07.02`.

## 📱 حالات الشاشة المختلفة (Screen States)

### 1. حالة الوردية النشطة مع وجود طلبات (Active Shift State)
الحالة الافتراضية أثناء أداء العمل الميداني، تظهر القائمة كاملة مع التحديث التلقائي للحالات بمجرد إتمام أي تسليم أو تسجيل بلاغ.

### 2. حالة الفلترة بدون نتائج (No Results Found)
عند كتابة كلمة بحث أو اختيار فلتر لا يحتوي على طلبات مطابقة:
- أيقونة بوكس فارغ مع نص توضيحي: *"لا توجد طلبات تطابق معايير البحث الحالية"*.
- زر لإعادة ضبط الفلاتر `[ عرض كافة الطلبات ]`.

### 3. حالة عدم وجود رحلة نشطة (No Active Trip Assigned)
إذا بدأ السائق الوردية ولكن لم يتم إسناد رحلة له بعد من قِبل مسؤول التوصيل:
- رسم توضيحي للسائق في وضع الانتظار.
- رسالة: *"لا توجد رحلة أو طلبات مسندة لك حالياً. سيتم إشعارك فور اكتمال التجهيز وإسناد الرحلة"*.
- زر لتحديث الحالة يدوياً `[ 🔄 تحديث ]`.

### 4. حالة انقطاع الاتصال بالإنترنت (Offline Mode)
- شريط علوي برتقالي: *"أنت تعمل بدون اتصال بالإنترنت (Offline). يتم حفظ العمليات محلياً وستتم المزامنة تلقائياً عند عودة الشبكة"*.

### 2. التزامن اللحظي عبر SignalR (Real-time Events)
تتصل الشاشة بـ `DriverHub` عبر الرابط `/hubs/driver` وتستمع للأحداث اللحظية لتحديث القائمة دون الحاجة للسحب للتحديث (`Pull to Refresh`):

| اسم الحدث (SignalR Event) | المتغيرات المرسلة | التأثير الفوري على شاشة الطلبات |
| :--- | :--- | :--- |
| `box-delivered` | `{ boxId, status: "Delivered", deliveredAtUtc }` | تحديث شارة البوكس إلى `[ تم التسليم ]` بالأخضر ونقله لعداد المسلمة. |
| `delivery-failed` | `{ boxId, reasonCategory, status: "Failed" }` | تمييز الكارت بالأحمر وإضافة شارة البلاغ. |
| `driver-arrived-at-customer`| `{ boxId, status: "ArrivedAtCustomer" }` | تحديث الكارت إلى "وصل السائق لموقع العميل". |
| `driver-requested-reassignment`| `{ boxId, status: "ReassignmentRequested" }` | إظهار حالة الطلب تحت إعادة الإسناد لمسؤول التوصيل. |
| `trip-in-transit` | `{ tripId, status: "InProgress" }` | تحديث حالة الرحلة بالكامل إلى جارية. |

## 🛡️ قواعد العمل والأمان (Business Rules & Security)

1. **الخلو التام من البيانات الوهمية (Strict Zero Mock Data):**
   - كافة الصناديق، العناوين، أرقام الهواتف، والوجبات مستمدة حصرياً من جدول `TripStops` وجلسة السائق الحقيقية في قاعدة البيانات.
   - إذا لم يكن للسائق رحلة جارية، تُعرض حالة الانتظار النظيفة (`Empty State`) ولا يتم اختلاق طلبات تجريبية نهائياً.
2. **الترتيب الملاحي الصارم (Route Optimized Ordering):**
   - تُرتّب البطاقات وفق الحقل `SequenceNumber` المحسوب في خوارزمية توجيه الرحلة لتقليل وقت القيادة والمسافة.
3. **أمان أرقام الهواتف (Data Privacy & Masking):**
   - يتاح خيار الاتصال المقنع عبر البوابة الافتراضية `GET /api/v1/driver/orders/{boxId}/call-proxy` لضمان عدم كشف الرقم الشخصي للعميل أو السائق.
4. **دعم العمل في وضع عدم الاتصال (Offline Resilience):**
   - يتم تخزين كاش محلي للطلبات المسندة بواسطة `SQLite / Hive` محلياً في تطبيق الهاتف لتمكين السائق من متابعة العناوين حتى في مناطق ضعف التغطية.
