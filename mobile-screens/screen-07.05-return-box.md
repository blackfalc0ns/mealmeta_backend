# 07.05 - إيداع البوكس المرتجع للمطبخ (Return Box to Kitchen)

## 📌 نظرة عامة (Overview)
* **رقم الشاشة وتسميتها:** `07.05 - إيداع البوكس المرتجع للمطبخ (Return Box to Kitchen)`
* **الهدف التشغيلي:** توثيق إعادة البوكس المتعثر إلى المطبخ/المطعم لإغلاق عهدة السائق. نظراً لأن الوجبات يتم تسليمها في بوكسات طعام عادية غير مستردة في الأحوال الطبيعية، فإن هذه الشاشة تخص حصراً **البوكسات التي تعذر تسليمها للعميل** والتي يجب إعادتها فوراً للمطبخ لضمان سلامة الأغذية وتبرئة ذمة السائق قبل إنهاء الوردية.
* **المستخدم المستهدف:** السائق الميداني (Driver).

---

## 🎨 عناصر واجهة المستخدم وتجربة الاستخدام (UI / UX Elements)

### 1. الشريط العلوي والتعليمات (Header & Info Card)
* عنوان رئيسي: **"إيداع البوكس المرتجع"**.
* عنوان فرعي: *"أعد البوكس إلى المطعم"*.
* كارت إرشادي برتقالي/رمادي:
  > *"عند تعذر تسليم الطلب، يجب إعادة البوكس إلى المطبخ وإثبات الإيداع لإغلاق العهدة ومتابعة إنهاء الوردية."*

### 2. بطاقة بيانات البوكس المرتجع (Returned Box Card)
* **كود البوكس:** `BX-458722`.
* **نوع البوكس:** `بوكس طعام عادي (Standard Disposable Meal Box)`.
* **المطبخ المستلم:** المطبخ السحابي الرئيسي (Main Kitchen Hub).
* **اسم العميل الأصلي:** أحمد إبراهيم.

### 3. سبب الإرجاع والملاحظات (Return Reason & Details)
* **سبب الإرجاع:** مسترجع آلياً من بلاغ التعذر (مثل: *"تعذر التسليم لعدم رد العميل"*).
* **تفاصيل إضافية (اختياري):** حقل نصي لكتابة اسم موظف الاستلام بالمطبخ (مثل: "تم التسليم لمشرف المطبخ الشيف علاء").

### 4. قسم توثيق إثبات الإيداع بالصورة (Return Proof Photo)
* زر التقاط صورة:
  * `[ إرفاق صورة إثبات الإيداع بالمطبخ 📷 ]`.
  * تظهر صورة البوكس في منطقة المرتجعات بالمطبخ مع تاريخ ووقت الإيداع لضمان عدم حدوث أي لبس.

### 5. أزرار الإجراءات (Action Buttons)
* **الزر الرئيسي البنفسجي:**
  * `[ تأكيد الإيداع للمطعم ]` (Confirm Return to Restaurant).
  * يحدث حالة البوكس إلى `ReturnedToKitchen` ويبرئ ذمة السائق بالكامل.
* **زر الإلغاء:**
  * `إلغاء` للعودة للشاشة السابقة في حال تمكن السائق من الوصول للعميل وتسليم الطلب.

## 🔌 تكامل الواجهة الخلفية (Backend API Integration)

### توثيق إيداع البوكس المرتجع بالمطبخ
```http
POST /api/v1/driver/orders/{boxId}/return-to-kitchen HTTP/1.1
Authorization: Bearer <driver_token>
Content-Type: application/json

{
  "reason": "تعذر التسليم لعدم رد العميل",
  "notes": "تم تسليم البوكس لمسؤول الاستلام بالمطبخ",
  "returnProofPhotoStorageKey": "returns/ret_BX458722_20260923.jpg",
  "latitude": 29.3759,
  "longitude": 47.9774
}
```

**نموذج الاستجابة (Response):**
```json
{
  "boxId": "c2222222-2222-2222-2222-222222222222",
  "boxCode": "BX-458722",
  "status": "ReturnedToKitchen",
  "message": "تم إيداع البوكس BX-458722 بالمطبخ وإغلاق العهدة بنجاح.",
  "returnedAtUtc": "2026-09-23T08:35:45Z"
}
```

### أحداث البث المباشر (SignalR)
* يبث الخادم حدث `box-returned-to-kitchen` إلى لوحة تحكم مسؤول التوصيل (`DispatcherHub`) لإزالة البوكس من قائمة المعلقات وتحديث سجل العمليات.

## 🔒 قواعد العمل والتحقق (Business Rules)
1. **فك حظر إنهاء الوردية:** لا يسمح للسائق بإنهاء ورديته (End Shift) طالما يوجد بوكس بحالة `Pending` أو `PickedUp`، ولكن بمجرد تحويل البوكس المتعثر إلى `ReturnedToKitchen`، يُسمح له بإنهاء الوردية بشكل طبيعي.
2. البوكسات المسلمة بنجاح للعملاء لا تعود للمطبخ إطلاقاً لأنها عبوات عادية مخصصة للاستخدام الفردي (Standard Disposable Boxes).
