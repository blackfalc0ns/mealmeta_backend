# 07.03 - تأخير في التوصيل (Delivery Delayed)

## 📌 نظرة عامة (Overview)
* **رقم الشاشة وتسميتها:** `07.03 - تأخير في التوصيل (Delivery Delayed)`
* **الهدف التشغيلي:** شاشة تحذيرية تظهر تلقائياً عندما يتجاوز السائق نافذة وقت التسليم المتوقعة للطلب المحدد (ETA Exceeded). تتيح للسائق إشعار الدعم ومسؤول الحركة بسبب التأخير (ازدحام، عطل)، أو متابعة مسار التوصيل.
* **المستخدم المستهدف:** السائق الميداني (Driver).

---

## 🎨 عناصر واجهة المستخدم وتجربة الاستخدام (UI / UX Elements)

### 1. الشريط العلوي والوسم (Top Navigation & Status Badge)
* زر تراجع `<`.
* عنوان الشاشة: **"تفاصيل التوصيل"**.
* رقم الطلب: `#BX-1256`.
* شارة الحالة التحذيرية: `جاري التوصيل` (خلفية صفراء/برتقالية بنص كهرماني غامق).

### 2. الرسم التوضيحي للوقت والتحذير (Time & Warning Graphic)
* رسم توضيحي لساعة حائط كبيرة ⏰ مع مثلث تحذير برتقالي بارز ⚠️ للإشارة إلى نفاد الوقت المجدول.

### 3. رسالة التنبيه الإرشادية (Alert Text)
* عنوان بارز: **"تأخير في التوصيل"**.
* نص تفصيلي:
  > *"أنت متأخر عن وقت التسليم المتوقع، يرجى الإسراع في التوصيل أو التواصل مع الدعم إذا واجهت مشكلة."*

### 4. بطاقة الوقت المتوقع وبيانات التأخير (Expected Delivery Time Card)
* **الوقت المتوقع:** `12:30 م`.
* **مقدار التأخير المحسوب:** `+15 دقيقة` (أو الوقت المتبقي المقدر).

### 5. أزرار الإجراءات (Action Buttons)
* **الزر الرئيسي البنفسجي:**
  * `[ تواصل مع الدعم 🎧 ]` (Contact Support).
  * يفتح قناة الاتصال الفوري بمركز دعم العمليات (Dispatcher Support) لطلب المساعدة أو الإبلاغ عن اختناق مروري.
* **الزر الثانوي:**
  * `[ متابعة التوصيل ]` (Resume Delivery).
  * يعيد السائق مباشرة إلى شاشة الملاحة الحية `07.01` لمواصلة التحرك نحو العميل.

---

## 🔌 تكامل الواجهة الخلفية (Backend API Integration)

### إرسال تقرير التأخير إلى مسؤول التوصيل والدعم
```http
POST /api/v1/driver/orders/{boxId}/report-delay HTTP/1.1
Authorization: Bearer <driver_token>
Content-Type: application/json

{
  "delayMinutes": 15,
  "reason": "ازدحام مروري خانق على طريق الدائري الرابع"
}
```

**نموذج الاستجابة (Response):**
```json
{
  "isSuccess": true,
  "value": true
}
```

### أحداث البث المباشر (SignalR)
* يبث الخادم حدث `delivery-delay-reported` إلى لوحة تحكم مسؤول التوصيل (`DispatcherHub`) لتحديث شارة حالة الطلب على خريطة المراقبة الحية (الشاشة `04.02 / 04.06`).

---

## 🔒 قواعد العمل والتحقق (Business Rules)
1. يتم احتساب التأخير تلقائياً بمجرد تجاوز وقت نهاية النافذة الزمنية المخصصة للمحطة (`SlotLabel` مثل 12:30 م) بـ 5 دقائق.
2. لا يتم إيقاف الوردية أو سحب الطلب بمجرد التأخير، بل يتاح للسائق دائماً خيار `[ متابعة التوصيل ]` لإكمال مهمته.
