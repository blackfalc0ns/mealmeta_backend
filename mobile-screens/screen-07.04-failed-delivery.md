# 07.04 - تعذر التسليم وبلاغ المشرف (Failed Delivery)

## 📌 نظرة عامة (Overview)
* **رقم الشاشة وتسميتها:** `07.04 - تعذر التسليم وبلاغ المشرف (Failed Delivery)`
* **الهدف التشغيلي:** شاشة معالجة الحالات الاستثنائية التي يستحيل فيها تسليم البوكس للعميل (عدم الرد بعد عدة اتصالات، عنوان غير صحيح، رفض الاستلام). يقوم السائق بتسجيل سبب التعذر، التقاط صورة إثبات، وإرسال بلاغ فوري لنظام الإدارة ليتم تحويل البوكس للمرتجعات (الشاشة `07.05`).
* **المستخدم المستهدف:** السائق الميداني (Driver).

---

## 🎨 عناصر واجهة المستخدم وتجربة الاستخدام (UI / UX Elements)

### 1. الشريط العلوي وشارة الحالة (Header & Status Badge)
* زر تراجع `<`.
* عنوان الشاشة: **"تفاصيل التوصيل"**.
* رقم الطلب: `#BX-1256`.
* شارة الحالة: `تعذر التسليم` (لون أحمر تحذيري مع خلفية وردية فاتحة).

### 2. الرسم التوضيحي للتعذر (Failed Delivery Graphic)
* خريطة ورقية مطوية مع دبوس موقع أحمر يعلوه علامة خطأ 📍❌ توضح تعذر الوصول للمستلم.

### 3. الرسالة والتعليمات (Alert Text & Instructions)
* عنوان رئيسي بخط أحمر/داكن: **"تعذر التسليم"**.
* نص تفصيلي:
  > *"لم يتم تسليم الطلب للعميل، يرجى تحديد سبب التعذر وإرسال بلاغ."*

### 4. أسباب التعذر وملاحظات السائق (Reasons Dropdown & Input)
* **قائمة أسباب التعذر المعيارية:**
  * العميل لا يجيب على الهاتف (Customer Unreachable - 3 محاولات اتصال).
  * العنوان غير صحيح أو ناقص (Wrong Address).
  * رفض العميل استلام الوجبة (Customer Refused).
  * تعذر الوصول للمبنى / بوابة مغلقة (Inaccessible Location).
  * إلغاء الطلب من قبل العميل (Customer Cancelled).
  * سبب آخر (Other).
* **حقل الملاحظات النصية:** شرح إضافي لما حدث ميدانياً.
* **إرفاق صورة إثبات:** صورة لسجل الاتصالات، أو باب المبنى، أو لافتة الشارع.

### 5. أزرار الإجراءات (Action Buttons)
* **الزر الرئيسي:**
  * `[ إرسال بلاغ ]` (Send Incident Report).
  * بالضغط عليه: يتم تسجيل فشل المحطة (`TripStopStatus.Failed`)، وإشعار المشرف، وتوجيه السائق لشاشة إرجاع البوكس `07.05 - إيداع البوكس المرتجع`.
* **الزر الثانوي:**
  * `[ إعادة المحاولة ]` (Retry Delivery).
  * يعيد السائق لشاشة التأكيد `07.02` لإعادة الاتصال بالعميل والمحاولة مجدداً.
* **رابط نصي سفلي:**
  * `تواصل مع الدعم` للاتصال بمركز مساندة السائقين.

## 🔌 تكامل الواجهة الخلفية (Backend API Integration)

### تسجيل تعذر التسليم ورفع البلاغ
```http
POST /api/v1/driver/orders/{boxId}/fail-delivery HTTP/1.1
Authorization: Bearer <driver_token>
Content-Type: application/json

{
  "reasonCategory": "CustomerUnreachable",
  "notes": "تم الاتصال بالعميل 3 مرات ولم يتم الرد، وانتظرت 10 دقائق أمام المبنى",
  "proofPhotoStorageKey": "proofs/unreachable_BX1256.jpg",
  "latitude": 29.3801,
  "longitude": 47.9852
}
```

**نموذج الاستجابة (Response):**
```json
{
  "boxId": "c2222222-2222-2222-2222-222222222222",
  "boxCode": "BX-1256",
  "status": "Failed",
  "reasonCategory": "CustomerUnreachable",
  "message": "تم تسجيل تعذر التسليم للبوكس BX-1256 وإشعار المشرف.",
  "failedAtUtc": "2026-09-23T08:35:30Z"

```

## 🔒 قواعد العمل والتحقق (Business Rules)
1. تتطلب المنظومة إجراء محاولة اتصال بالعميل لتوثيق التعذر عند اختيار "العميل لا يجيب".
2. تحويل الطلب لحالة `Failed` لا يسقط عهدة البوكس عن السائق، بل يلزمه نظام العمل بالتوجه لإيداع البوكس المرتجع بالمطبخ (الشاشة `07.05`) أو تسليمه لسائق بديل.
