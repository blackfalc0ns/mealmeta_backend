# 07.02 - تم الوصول إلى موقع العميل وتأكيد التسليم (Customer Arrival & Delivery Confirmation)

## 📌 نظرة عامة (Overview)
* **رقم الشاشة وتسميتها:** `07.02 - تم الوصول إلى موقع العميل وتأكيد التسليم (Customer Arrival & Delivery Confirmation)`
* **الهدف التشغيلي:** تأكيد تسليم البوكس بعد مسح نفس QR المستخدم عند تحميل الطلب مع صورة إثبات التسليم. OTP غير مدعوم ولا يحل محل مسح QR.
* **المستخدم المستهدف:** السائق الميداني (Driver).

---

## 🎨 عناصر واجهة المستخدم وتجربة الاستخدام (UI / UX Elements)

### 1. شريط الحالة والتأكيد العلوي (Arrival Banner)
* أيقونة موقع وبطاقة مرحلية بنفسجية مع علامة ✓:
  * العنوان: **"تم الوصول إلى موقع العميل"**.
  * العنوان الفرعي الإرشادي: *"يرجى تأكيد تسليم الطلب ومطابقة التسليم"*.

### 2. بطاقة تفاصيل العميل والطلب (Customer & Order Card)
* **اسم العميل:** أحمد إبراهيم.
* **رقم هاتف العميل:** `+965 98765432` مع زر مكالمة هاتفية سريعة 📞.
* **العنوان وموقع التسليم:** شارع النصر، الدور 4، شقة 12.
* **وقت الوصول الفعلي:** `12:15 م`.
* **كود الطلب والبوكس:** `#BX-1256` (بوكس طعام عادي - Normal Box).
* **ملخص الوجبات:** `3 وجبات طعام عادية`.

### 3. مسح QR البوكس (إجباري)
> [!IMPORTANT]
> يجب مسح نفس QR المستخدم وقت التحميل. الصورة وحدها لا تسمح بتأكيد التسليم. نجاح قراءة الكاميرا لا يعني نجاح المطابقة؛ السيرفر يتحقق عند إرسال طلب التسليم.

* زر `[ مسح QR البوكس ]` يفتح الكاميرا ويضع نتيجة القراءة الجديدة في `barcodeValue`.
* يبدأ الكود فارغاً لكل طلب، ويُمسح عند تغيير الطلب أو إعادة فتح الشاشة. لا تتم تعبئته من كود العرض أو سجل التحميل أو مسح طلب سابق.
* تعرض الواجهة «تم المسح — سيتم التحقق عند تأكيد التسليم» بعد القراءة، وتطلب إعادة المسح إذا رفضه السيرفر.
* لا يُستخدم مسار تحقق التحميل هنا، ولا تُعرض حقول OTP أو إعادة إرساله لأن السيرفر لا يتحقق منه.

### 4. قسم توثيق حالة البوكس بالصورة (إجباري - Mandatory Proof Photo)
* زر كاميرا عريض أو معاينة الصورة الملتقطة:
  * أيقونة كاميرا 📷 مع نص: `[ التقاط صورة إثبات التسليم وحالة البوكس ]`.
  * عند التقاط الصورة: تظهر صورة مصغرة (Thumbnail) مع علامة صح خضراء وزر `[ إعادة الالتقاط ]`.
* الغرض: توثيق سلامة تغليف البوكس العادي وتركه عند باب العميل أو تسليمه باليد لمنع أي نزاعات لاحقة.

### 5. زر الإجراء الرئيسي السفلي (Primary Action Button)
* زر بنفسجي عريض مميز:
  * `[ تأكيد تسليم الطلب ]` (Confirm Order Delivery).
  * **شروط التفعيل:** مسح QR جديد لهذا الطلب ورفع صورة الإثبات، مع تعطيل الزر أثناء الإرسال.
  * ينتقل إلى `07.06` فقط بعد نجاح السيرفر في مطابقة الكود وإتمام التسليم؛ عند الرفض تظل الشاشة مفتوحة.

## 🔌 تكامل الواجهة الخلفية (Backend API Integration)

### 1. إتمام التسليم للعميل (Delivery Confirmation Endpoint)
```http
POST /api/v1/driver/orders/{boxId}/deliver HTTP/1.1
Authorization: Bearer <driver_token>
Content-Type: application/json

{
  "proofPhotoStorageKey": "proofs/deliv_BX1256_20260923.jpg",
  "deliveryOtp": "4729",
  "barcodeValue": "BX-1256",
  "handoverNotes": "تم التسليم للعميل باليد عند الباب",
  "latitude": 29.3801,
  "longitude": 47.9852
}
```
* **إلزامي:** `barcodeValue` و`proofPhotoStorageKey`. الكود يجب أن يطابق كامل كود التحميل المسجل لنفس الطلب والرحلة والسائق. الصورة يجب أن تشير إلى رفع حقيقي مملوك للسائق ضمن `uploads/drivers/delivery/`. `handoverNotes` اختياري، و`deliveryOtp` لا يتم التحقق منه.

**نموذج الاستجابة (Response):**
```json
{
  "boxId": "c2222222-2222-2222-2222-222222222222",
  "boxCode": "BX-1256",
  "status": "Delivered",
  "message": "تم تسليم البوكس BX-1256 وتوثيق الإثبات بنجاح",
  "deliveredAtUtc": "2026-09-23T08:35:10Z"
}
```

### 2. الأخطاء والمزامنة
* `Orders.DeliveryBarcodeRequired`: يجب مسح QR قبل التأكيد.
* `Orders.DeliveryPickupScanRequired`: لا يوجد سجل تحميل لنفس الطلب والرحلة والسائق؛ لا يسمح بتجاوز ذلك بالصورة.
* `Orders.BarcodeMismatch`: الكود الممسوح لا يطابق كود التحميل كاملاً؛ اطلب مسح البوكس الصحيح.
* نفس التحقق ينطبق على مزامنة `deliver` / `delivery` / `deliveryconfirmation`. لا تعرض تسليماً مؤكداً قبل قبول السيرفر للمزامنة.

## 🔒 قواعد العمل والتحقق (Business Rules)
1. **إجبارية QR:** يرفض السيرفر التأكيد دون مسح نفس QR المستخدم عند التحميل. لا يقبل جزءاً من الكود أو كود طلب عميل آخر. OTP لا يحل محل المسح.
2. **إجبارية الصورة:** يرفض النظام تأكيد التسليم مع ظهور خطأ `Orders.ProofPhotoRequired` إذا لم ترفق صورة إثبات التسليم.
3. **تحديث رصيد الوردية:** فور نجاح التسليم، يزداد عداد الوجبات المكتملة للسائق تلقائياً (`activeSession.CompletedOrdersCount += 1`).
4. **فحص اكتمال الرحلة:** إذا كان هذا هو الطلب الأخير في الرحلة، يتم تحويل حالة الرحلة بالكامل إلى `Completed` ويتم توجيه السائق لشاشة ملخص انتهاء العمل `05.03`.
