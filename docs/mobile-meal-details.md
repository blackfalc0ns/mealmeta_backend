# للموبايل: فتح تفاصيل الوجبة من صفحة المطعم

بعد اختيار الباقة وفتح صفحة المطعم، عند الضغط على وجبة اطلب تفاصيلها بالمسار المختصر:

```http
GET /api/v1/customer/subscription-flow/bundles/{bundleId}/meals/{mealId}
Authorization: Bearer <customer-token>
```

المطلوب من الموبايل:

- `bundleId`: معرّف الباقة التي اختارها المستخدم؛ احتفظ به أثناء خطوات الاشتراك.
- `mealId`: معرّف الوجبة التي ضغط عليها من قائمة وجبات المطعم.

لا تحتاج إلى إرسال `programId` أو `restaurantId`، ولا يوجد Body أو Query Parameters إضافية. السيرفر يعرف البرنامج من الباقة، والمطعم من الوجبة، حتى لو المستخدم اختارها من صفحة المطعم.

مثال لبناء الرابط في Dart:

```dart
final path = '/api/v1/customer/subscription-flow/bundles/$bundleId/meals/$mealId';
```

**لماذا نرسل الباقة؟** أهلية المطعم والوجبة تعتمد على الباقة المختارة، والوجبة قد تظهر في أكثر من برنامج؛ لذلك لا نكتفي بـ `mealId` وحده.

الـ Response بنفس شكل تفاصيل الوجبة في المسار القديم (`CustomerRestaurantBrowseMealDetailsDto`). استخدم نفس الموديل وشاشة التفاصيل الحالية؛ التعديل في رابط الطلب والمدخلات فقط. تحققات الإتاحة وأهلية المطعم وحساسية وتفضيلات العميل مستمرة كما هي.

إذا رجع `404`، اعرض أن الوجبة أو الباقة أو المطعم غير متاح حسب كود `error` في الرد. المسار القديم ما زال مدعومًا للتوافق.

هذا الطلب لعرض تفاصيل الوجبة فقط؛ اختيارها أو حفظها في جدول الاشتراك يستمر من خلال مساره الحالي.

## حقول التصميم الجديد

- `ingredients[].weightG`: وزن المكون بالجرام من حصة المكون داخل الوجبة. عند عدم تسجيل وزن موجب يرجع `null`؛ أخفِ الوزن بدل عرض صفر.
- `nutrition.perMeal`: القيم الغذائية للوجبة كاملة، بما فيها `fiberG` ونسب الماكروز.
- `nutrition.per100g`: القيم محسوبة من وزن الوجبة المسجل: القيمة للوجبة × 100 ÷ وزن الوجبة بالجرام، مع التقريب لخانتين. نسب الماكروز نفسها في الوضعين. إذا الوزن غير موجود أو غير موجب يرجع `null`؛ أخفِ أو عطّل اختيار «لكل 100 جم». أي قيمة غذائية غير مسجلة تظل `null`.
- `tags[]`: كل شارة تحتوي `id`, `nameAr`, `nameEn`, `iconType`. تظهر الشارات المسجلة فقط؛ وقد تكون القائمة فارغة. حدد الأيقونة من `iconType` ولا تعتمد على ترتيب المصفوفة.

| id | النص العربي | iconType |
| --- | --- | --- |
| high_protein | عالي البروتين | protein |
| diet_friendly | مناسب للدايت | diet |
| natural | مكونات طبيعية | leaf |

قد تظهر وسوم أخرى من كتالوج التفضيلات الغذائية بأيقونة `tag`. حقول التغذية القديمة مثل `nutrition.calories` مستمرة للتوافق؛ الشاشة الجديدة تستخدم `perMeal` أو `per100g` حسب الـ Toggle. التحديث يشمل مسار التفاصيل القديم والمختصر.

مثال جزئي للحقول الجديدة لوجبة وزنها 350 جم (الأرقام محسوبة وليست منسوخة من التصميم):

```json
{
  "tags": [
    { "id": "high_protein", "nameAr": "عالي البروتين", "nameEn": "High Protein", "iconType": "protein" }
  ],
  "nutrition": {
    "perMeal": { "calories": 550, "proteinG": 65, "carbsG": 60, "fatG": 15, "fiberG": 7, "proteinPercent": 41, "carbsPercent": 38, "fatPercent": 21 },
    "per100g": { "calories": 157.14, "proteinG": 18.57, "carbsG": 17.14, "fatG": 4.29, "fiberG": 2, "proteinPercent": 41, "carbsPercent": 38, "fatPercent": 21 }
  },
  "ingredients": [
    { "ingredientId": "11111111-1111-1111-1111-111111111111", "nameAr": "دجاج مشوي", "nameEn": "Grilled Chicken", "weightG": 180, "iconUrl": "https://example.com/chicken.png" }
  ]
}
```
