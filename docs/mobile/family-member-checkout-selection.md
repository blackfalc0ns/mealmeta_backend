# اختيار الاشتراك الآن مستقل لكل فرد

## الطلب

```http
PUT /api/v1/customer/family-subscription-flow/members/{memberId}/checkout-selection
Content-Type: application/json
```

```json
{
  "subscribeNow": false
}
```

`false` يعني تأجيل شراء اشتراك هذا الفرد، و`true` يعني اختياره للدفعة القادمة. لا يبدأ الطلب اشتراكًا مدفوعًا، ولا يمسح بيانات الفرد أو خطته، ولا يوقف وصول حسابه.

## الرد

رد العملية هو `FamilyCheckoutSelectionDto` وحقوله:

- `memberId`: الفرد الذي تغير اختياره.
- `checkoutSelected`: اختيار هذا الفرد بعد الحفظ.
- `selectedNewSubscriberCount`: عدد الأفراد المختارين الآن في الدفعة، وليس حالة كل فرد.
- `batchId` و`batchVersion`: هوية وإصدار الدفعة بعد التغيير.

هذه العملية تغير الفرد الموجود في مسار الطلب فقط. لا تطبق `checkoutSelected` على كل `members`. حدّث العنصر الذي يطابق `memberId`، ثم أعد جلب `current` أو `summary?memberId={memberId}`، واقرأ `members[].subscribeNow` لكل فرد مستقلًا.

```dart
final changedId = response['memberId'];
final selected = response['checkoutSelected'] as bool;
// استخدم copyWith الخاصة بموديل المشروع، دون تعديل اختيار باقي العناصر.
members = members.map((member) => member.memberId == changedId
    ? member.copyWith(subscribeNow: selected)
    : member).toList();
```

ضع حالة السويتش والتحمّل لكل `memberId`، واستخدم مفتاح عنصر ثابتًا بمعرفه، بدل متغير Boolean مشترك بين بطاقات الأفراد. امنع الطلبات المتداخلة لنفس الفرد، وتجاهل رد الملخص القديم إذا تغير السياق أثناء التحميل. تجنب إرسال الطلب نفسه لكل أفراد العائلة من حدث تغيير سويتش واحد.

## إصلاح أول تغيير

في العائلات القديمة التي لم يكن لها اختيار محفوظ في دفعة مفتوحة، كان `current` والملخص يعرضان غير المشتركين على أنهم مختارون. إنشاء أول اختيار لفرد واحد كان يترك الباقي خارج الدفعة، فيتحولون إلى غير مختارين رغم عدم تغييرهم.

أصبح أول حفظ يحتفظ بنفس الحالات المعروضة لباقي الأفراد النشطين غير المشتركين، ثم يغير الفرد المطلوب فقط. إذا كانت هناك دفعة مفتوحة بها اختيارات صريحة، فلا يعيد تهيئة اختياراتها ولا يعيد اختيار الأفراد المؤجلين. الأفراد المدفوعون أو المحذوف وصولهم لا يدخلون في الاختيارات الابتدائية.

## التحقق

نجح 19 اختبارًا لخدمة اختيار أفراد العائلة، و80 اختبارًا لمسارات فلو العائلة. تشمل الحالات أول تغيير إلى `true` و`false`، تغيير فرد ثانٍ دون تغيير الأول، الحفاظ على اختيار مؤجل محفوظ، المدفوعين والمحذوفين، ورفض التغيير أثناء الدفع المعلق.
