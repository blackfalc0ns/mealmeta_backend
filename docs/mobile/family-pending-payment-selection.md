# الضغط على اشتراك الآن أثناء دفع عائلي معلّق

## المسار نفسه

```http
PUT /api/v1/customer/family-subscription-flow/members/{memberId}/checkout-selection
```

```json
{"subscribeNow": true}
```

عند وجود محاولة Initial معلقة صالحة ورابط بوابة محفوظ، يرجع المسار `200` وبيانات استكمال الدفع بدل `409`. لا ينشئ فاتورة أخرى، ولا يغير أفراد أو سعر الفاتورة المعلقة. تحقق الملكية وإزالة العضو يظل مطبقًا قبل إرجاع بيانات الدفع.

## الحقول المضافة إلى رد الاختيار

| الحقل | النوع | المعنى |
|---|---|---|
| `pendingCheckout` | object/null | نفس عقد FamilyCheckoutStartedDto، ويتضمن paymentUrl الحقيقي وbatchId وbatchVersion والسعر وانتهاء الحجز |
| `retryPaymentEndpoint` | string/null | `/api/v1/customer/family-subscription-flow/retry-payment` عندما يمكن إعادة الدفع |
| `nextScreen` | string/null | `family_payment` عند استكمال الدفع؛ null للاختيار العادي |
| `selectionApplied` | boolean | false عند إعادة بيانات فاتورة معلقة دون تعديل اختيار الفرد؛ true عند حفظ الاختيار في مسودة |

تبقى الحقول `batchId`, `batchVersion`, `memberId`, `checkoutSelected`, `selectedNewSubscriberCount` موجودة. `checkoutSelected` يعكس الاختيار الفعلي داخل الفاتورة، وليس نسخة من الطلب.

إذا كان الفرد غير موجود في الفاتورة وطلب subscribeNow=true، يرجع `checkoutSelected=false`, `selectionApplied=false` مع بيانات دفع الفاتورة الحالية. لا يعرض الموبايل أن الفرد تمت إضافته أو أن الدفع سيشمله. يجب إنهاء المحاولة الحالية أو انتظار انتهاء حجزها ثم حفظ اختيارات جديدة؛ لا يمكن تغيير المشاركين تحت فاتورة يمكن دفعها بالفعل.

## ربط الموبايل

1. أرسل PUT عند الضغط واقرأ جسم الرد حتى لو كان 200.
2. إذا كان `nextScreen=family_payment` و`pendingCheckout.paymentUrl` موجودًا، افتح الرابط مباشرة في شاشة الدفع الموجودة. لا تعيد إنشاء المجموعة أو ترسل checkout جديدًا.
3. إذا كان `nextScreen=family_payment` وpendingCheckout=null وretryPaymentEndpoint موجودًا، فقد انتهت المحاولة السابقة وتم حفظ اختيار المسودة. أرسل POST إلى retryPaymentEndpoint باستخدام callbackUrl/errorUrl وإعدادات الدفع الفعلية في التطبيق، ثم افتح paymentUrl من الرد. راجع family-payment-retry-button.md.
4. اعرض حالة الفرد من `checkoutSelected`. إذا كان selectionApplied=false فلا تعرض تأكيدًا بأن الاختيار تغير. استخدم نصًا عربيًا وإنجليزيًا من موارد التطبيق يوضح أن الدفع الجاري يخص اختيارات الفاتورة الحالية.
5. عند الرد العادي دون nextScreen، أكمل مسار المسودة والملخص المعتاد.
6. بعد العودة من البوابة نفذ التحقق الحالي وأعد جلب الحالة؛ فتح الرابط ليس دفعًا ولا تفعيلًا.

## حالات ما زالت ترفض التعديل

- subscribeNow=false أثناء فاتورة معلقة: 409 family.checkout_pending مع مسارات الاستكمال؛ لا يتم حذف الفرد من الفاتورة المفتوحة.
- ReviewRequired: لا يتم إرجاع مسار إعادة دفع ولا إنشاء فاتورة جديدة قبل حسم المراجعة.
- فاتورة معلقة بلا رابط صالح محفوظ: يرجع تعارض مع مسار الاستكمال؛ لا يختلق المسار رابط دفع ولا يعتمد رابطًا منتهيًا.
- عضو خارج عائلة المدير أو وصوله محذوف: رفض دون كشف بيانات الدفع.

الحجوزات المنتهية تُعالج بخدمة الانتهاء القائمة قبل فحص الاختيار، خارج قفل المعاملة لتجنب الأقفال المتداخلة. المسار لا يأخذ callbackUrl ولذلك لا ينشئ دفعًا جديدًا بنفسه عند انتهاء المحاولة؛ POST retry-payment يتولى ذلك بعقد الدفع المعتمد.

## تحقق الباك

تغطي الاختبارات استكمال عضو مختار أو غير مختار، تكرار الضغط دون فاتورة إضافية، رفض إزالة مشارك تحت فاتورة مفتوحة، منع تسريب البيانات لعضو خارج العائلة، استعادة الحجز المنتهي، وحجب زر الإعادة عند ReviewRequired رغم وجود محاولة منتهية أقدم. لا يحتوي هذا المستودع على Flutter؛ اختبار الواجهة يحتاج مشروع الموبايل.
