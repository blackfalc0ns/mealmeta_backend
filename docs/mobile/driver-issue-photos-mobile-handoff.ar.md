# ربط صور بلاغات السائق — تسليم للموبايل

هذا الملف يخص رفع صور البلاغ وربطها وعرضها فقط. **نجاح رفع الصورة `201` لا يربطها بالبلاغ تلقائياً**؛ يجب إرسال قيمة `storageKey` في طلب إنشاء البلاغ أو إضافة الصور.

كل مسارات API أدناه على نفس عنوان الباك، وتحتاج `Authorization: Bearer <accessToken>` بحساب السائق، إلا روابط العرض الموقعة الموضحة لاحقاً. أمثلة JSON توضيحية؛ استخدم القيم الفعلية الراجعة من الخادم.

## 1. ارفع كل صورة أولاً

`POST /api/v1/uploads` بصيغة `multipart/form-data`، وليس JSON:

| الحقل | القيمة |
|---|---|
| `file` | ملف الصورة نفسه |
| `scope` | `drivers` |
| `folder` | `issue-evidence` |

النجاح `201 Created`. مثال مختصر من الرد:

```json
{
  "storageKey": "https://cdn.example.com/account/uploads/drivers/issue-evidence/evidence.jpg",
  "readUrl": "https://cdn.example.com/account/uploads/drivers/issue-evidence/evidence.jpg",
  "contentType": "image/jpeg"
}
```

احتفظ بـ`storageKey` **كاملاً كما عاد، دون تعديل**. قد يكون رابط HTTPS كاملاً مثل ImageKit، أو مساراً مثل `uploads/drivers/issue-evidence/evidence.jpg`. لا تقص الرابط ولا تستخرج منه مساراً، ولا تستخدم `readUrl` بدلاً من `storageKey`، حتى لو تساويا في رد معين. لا ترسل مسار الملف المحلي على الجهاز.

## 2. اربط الصور بالبلاغ

اختر طلباً واحداً حسب حالة البلاغ.

### عند إنشاء بلاغ جديد

`POST /api/v1/driver/orders/{boxId}/report-issue`، بصيغة JSON:

```json
{
  "issueType": "DamagedBox",
  "description": "وصف المشكلة",
  "severity": "Medium",
  "evidencePhotoStorageKeys": [
    "https://cdn.example.com/account/uploads/drivers/issue-evidence/evidence.jpg"
  ]
}
```

`boxId` هو GUID محطة التوصيل `TripStop`، وليس رقم الطلب الظاهر أو `DailyOrderId`. استخدم مفاتيح الصور التي رفعتها في الخطوة الأولى. النجاح `200 OK` يعيد **سلسلة JSON تحتوي GUID البلاغ**؛ احفظها باسم `issueId`، وليست كائناً يحتوي حقلاً بهذا الاسم.

إنشاء البلاغ ليس آمناً للتكرار: إذا انتهت مهلة الطلب، أعد تحميل قائمة البلاغات وتحقق من إنشائه قبل إعادة الإرسال.

### عند إضافة الصور لبلاغ موجود

`POST /api/v1/driver/support/issues/{issueId}/photos`، بصيغة JSON:

```json
{
  "storageKeys": [
    "https://cdn.example.com/account/uploads/drivers/issue-evidence/evidence.jpg"
  ]
}
```

النجاح `200 OK` يعيد `issueId` و`status` و`evidenceUrls`. إعادة نفس المفتاح لبلاغ نشط لا تضيف الصورة مرتين. هذا المسار مناسب أيضاً لبلاغ تم إنشاؤه سابقاً بدون صور؛ لا تنشئ بلاغاً جديداً لمجرد إرفاق الصور.

الحد الإجمالي **3 صور لكل بلاغ**، والأنواع المقبولة `image/jpeg` و`image/png` و`image/webp`. يجب أن يكون الملف مرفوعاً بحساب السائق نفسه، ومسجلاً لدى الباك وموجوداً في التخزين. لا يمكن إضافة صور لبلاغ منتهٍ (`Resolved` أو `Closed` أو `Rejected`).

## 3. اعرض الصور من تفاصيل البلاغ

بعد نجاح الربط، وعند فتح البلاغ من جديد، اقرأ التفاصيل من الخادم:

| الشاشة | المسار | حقل الصور |
|---|---|---|
| السائق | `GET /api/v1/driver/support/issues/{issueId}` | `evidenceUrls`: مصفوفة روابط نصية |
| مسئول التوصيل، بحسابه وصلاحياته | `GET /api/v1/dispatcher/support/issues/{issueId}` | `evidencePhotos`: مصفوفة كائنات، رابط كل صورة داخل `url` |

لا تعتمد على المعاينة المحلية وحدها، ولا تحفظ روابط العرض المؤقتة كرابط دائم. قيمة الربط الدائمة هي `storageKey`، وقيمة العرض تُقرأ من رد التفاصيل.

- رابط HTTPS مطلق إلى ImageKit/CDN: اعرضه كما عاد. لا تضف إليه توكن API، ولا ترسل `Authorization` الخاص بالتطبيق إلى نطاق CDN الخارجي.
- رابط `/api/v1/uploads/content?...&readToken=...`: رابط قراءة موقع لصورة واحدة، صالح لمدة **15 دقيقة** ويمكن عرضه دون هيدر تسجيل الدخول. احتفظ بكل معاملات الرابط، بما فيها `readToken`. لو كان الرابط نسبياً، أضف عنوان الباك فقط.
- بعد انتهاء صلاحية رابط القراءة، أعد طلب تفاصيل البلاغ للحصول على رابط جديد ثم أعد تحميل الصورة. لا تحاول تعديل الرمز أو توليد رابط بنفسك.
- مسار المحتوى القديم بدون `readToken` يحتاج هيدر Bearer صالحاً وصلاحية القراءة. الأفضل استخدام روابط التفاصيل الجديدة.

لا تسجل توكن تسجيل الدخول أو روابط `readToken` في اللوجات.

## التحقق السريع قبل تسليم النسخة

1. ارفع صورة، ثم تأكد أن طلب البلاغ يحتوي `evidencePhotoStorageKeys`، أو أن طلب الإضافة يحتوي `storageKeys`، بالقيمة الكاملة الراجعة من الرفع.
2. تأكد من نجاح طلب الربط؛ لا تعتبر نجاح الرفع وحده نجاحاً للعملية كلها.
3. أعد جلب التفاصيل: يجب أن تحتوي `evidenceUrls` على الصور، ثم اخرج من الشاشة وافتحها مجدداً للتحقق من بقائها.
4. افتح نفس البلاغ بحساب مسئول التوصيل وتحقق من `evidencePhotos[].url`.
5. لو المصفوفة فارغة، راجع طلب الربط و`issueId`. لو الروابط موجودة والصورة لا تفتح، راجع طلب تحميل الصورة وجدّد التفاصيل إذا انتهت صلاحية الرابط.

دعم مفتاح ImageKit الكامل موجود في تعديل الباك `4bbf355` على `dev`. يجب نشر هذا التعديل على بيئة API المستخدمة حتى يعمل هناك؛ وجوده على Git وحده لا يثبت أنه منشور.
