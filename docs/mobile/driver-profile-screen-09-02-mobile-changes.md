# تعديلات الموبايل — Screen 09.02: الملف الشخصي والمركبة والوثائق

هذا الملف تعليمات تنفيذ لفريق الموبايل لتحديث `driver_profile_screen.dart` بناءً على عقد الباك الحالي. لا يتضمن تعديل كود Flutter نفسه. المرجع: [عقد Screen 09.02](../../mobile-screens/screen-09.02-driver-profile-vehicle.md).

## 1. مصدر بيانات الشاشة

استخدم طلبًا واحدًا لجلب الملف والإحصائيات والمركبة والوثائق والتعيين وآخر تذكرة دعم:

```http
GET /api/v1/driver/profile
Authorization: Bearer <driver-access-token>
Accept-Language: ar
Accept: application/json
```

غيّر `Accept-Language` إلى `en` حسب لغة التطبيق الحالية. جسم نجاح الطلب هو كائن الملف مباشرة؛ لا تضف افتراضًا بوجود غلاف `data` أو `result` لهذا المسار.

- لا ترسل `driverId`؛ الباك يحدد السائق من التوكن.
- لا ترسل اللغة في body أو `culture` أو `ui-culture` في query؛ هذا المسار يأخذها من الـ header فقط.
- يدعم الباك أيضًا `ar-KW` و`en-US` ويختار العربية أو الإنجليزية.
- راجع interceptor الشبكة: إذا كان يرسل `Language` أو `X-Language` أيضًا، يجب أن تطابق لغة التطبيق. `Language` ثم `X-Language` لهما الأولوية على `Accept-Language`؛ الأفضل إرسال `Accept-Language` وحده.
- عند غياب لغة مدعومة، الافتراضي `en`.
- لا ترسل `X-Bilingual: true` للعرض العادي في الموبايل. اعتمد على `fullName`؛ وجود `fullNameAr` و`fullNameEn` معًا غير مضمون في الاستجابة العادية.

## 2. ربط عناصر الشاشة بالحقول

احذف قيم العرض الثابتة للبيانات التالية، واربطها بالاستجابة:

| عنصر الشاشة | حقل JSON | سلوك العرض |
|---|---|---|
| اسم السائق | `fullName` | اعرض النص المترجم الذي أعاده الباك. |
| وصف السائق تحت الاسم | `driverDescription` | اعرضه كما هو؛ الباك يحدد الوصف وفق اعتماد ملف السائق. |
| رتبة السائق | `driverRank` | أخفِ الرتبة عند `null`؛ الوصف ليس رتبة أو مستوى أداء. |
| كود السائق | `driverCode` | اعرض القيمة كما وردت. حاليًا هي UUID الملف بدون شرطات، وليست كود موظف مثل `AMM-1256`. لا تُنشئ كودًا بديلًا محليًا. |
| رقم الهاتف | `phoneNumber` | يقبل `null`؛ أخفِ الصف أو اعرض نص «غير متاح» من ترجمة التطبيق. |
| صورة البروفايل | `profileImageUrl` | استخدم الرابط القادم من مزود التخزين، مع أيقونة مستخدم عند غيابه أو فشل التحميل. |
| حالة الاتصال | `isOnline`, `status`, `statusText` | استخدم `isOnline` للعلامة البصرية، و`statusText` للنص. الحالة Snapshot من آخر تحميل للشاشة. |
| التقييم | `averageRating` | رقم nullable؛ عند `null` اعرض «لا توجد تقييمات» بدل تقييم ثابت أو `0.0`. |
| عدد المراجعات | `reviewsCount` | اعرض العدد الفعلي، بما فيه `0`. |
| إجمالي الطلبات | `totalOrders` | اعرض الرقم الفعلي، بما فيه `0`. لا تسمِّه «الطلبات المكتملة»؛ يشمل الطلبات المسندة وغير المسلّمة. |
| نسبة القبول | `acceptanceRatePercent` | عند `null` أخفِ بطاقة النسبة أو اعرض «غير متاحة»؛ لا تعرض `0%` أو `100%`. |
| تاريخ الانضمام | `joinedAtUtc` | حوّل تاريخ UTC إلى توقيت العرض ونسّقه حسب لغة التطبيق؛ عند `null` أخفِ الصف أو اعرض «غير متاح». |
| نوع المركبة | `vehicle.vehicleTypeLocalized` | استخدم النص القادم من الباك؛ `vehicleType` هو الكود الأصلي. |
| موديل المركبة | `vehicle.vehicleModel` | nullable؛ لا تضع موديلًا افتراضيًا. |
| سنة الصنع | `vehicle.vehicleYear` | رقم nullable؛ أضف السنة بجوار الموديل فقط عند توفرها. |
| لون المركبة | `vehicle.vehicleColorLocalized` | اعرض النص عند توفره؛ احتفظ بـ `vehicleColor` كقيمة أصلية. النص الحر قد يُعاد بلغته الأصلية. |
| رقم اللوحة | `vehicle.vehiclePlate` | اعرض القيمة المخزنة؛ لا تستخدم لوحة من تصميم الشاشة. |
| محافظة اللوحة | `vehicle.plateGovernorate` | أخفِها عند `null`؛ لا تستنتجها من عنوان السائق أو موقعه. |
| اعتماد وثيقة المركبة | `vehicle.verificationStatus`, `vehicle.verificationStatusText` | النص للعرض والكود للتنسيق. هذه حالة مراجعة **وثيقة التسجيل** وليست اعتماد أسطول مستقلًا. |
| الوثائق | `documents` | ابنِ القائمة من العناصر الفعلية؛ لا تُنشئ صفوف وثائق غير موجودة. |
| المطعم أو المطبخ المعيّن | `assignment.restaurantName` | اعرضه عند توفره فقط. |
| الفرع المعيّن | `assignment.branchName` | اعرضه عند توفره؛ تعيين المطعم لا يضمن وجود تعيين فرع. |
| آخر تذكرة دعم | `latestSupportTicket` | عند `null` اعرض حالة فارغة أو أخفِ القسم؛ لا تعرض تذكرة ثابتة. |

**الحقول غير المتاحة حاليًا:** `acceptanceRatePercent` و`driverRank` و`vehicle.plateGovernorate` ترجع `null` لأن النموذج الحالي لا يملك مصدر بيانات مستقلًا لها. يجب أن تعمل الشاشة بهذه الحالة دون قيم تخمينية.

## 3. تعديل الـ models وطبقة البيانات

أنشئ أو حدّث model للاستجابة الرئيسية وثلاثة كائنات متداخلة: المركبة، التعيين، وتذكرة الدعم، بالإضافة إلى model لكل عنصر وثيقة. اتبع أسماء وأنماط طبقة البيانات الموجودة في مشروع Flutter؛ أسماء الملفات الجديدة تتحدد وفق هيكل المشروع.

- `driverProfileId`, `driverCode`: نصوص؛ لا تحوّل المعرّف أو الكود إلى رقم.
- `fullName`, `driverDescription`, `status`, `statusText`: نصوص.
- `isOnline`: boolean. لا تربط Online بتوفر السائق لقبول إسناد أو بوجود رحلة فقط.
- `averageRating`, `acceptanceRatePercent`: `double?`؛ اقرأ الرقم عبر `num` ثم `toDouble()` حتى لو JSON أعاد عددًا صحيحًا.
- `reviewsCount`, `totalOrders`: أعداد صحيحة، و`0` قيمة صحيحة وليست دليلًا على غياب البيانات.
- `joinedAtUtc`: `DateTime?`؛ استخدم parsing آمنًا قبل تنسيق العرض.
- `phoneNumber`, `profileImageStorageKey`, `profileImageUrl`, `driverRank`: نصوص nullable.
- `vehicle`: كائن في العقد الحالي؛ حقوله جميعها تقبل `null`، و`vehicleYear` من نوع `int?`.
- `documents`: قائمة قد تكون فارغة. لا تعامل القائمة الفارغة كخطأ تحميل أو تستبدلها بوثائق من التصميم.
- `assignment`: كائن nullable؛ داخله `restaurantId`, `restaurantName`, `branchId`, `branchName` كلها nullable.
- `latestSupportTicket`: كائن nullable، و`updatedAtUtc` داخله nullable.

لا تعتمد على وجود الاسمين `fullNameAr` و`fullNameEn` معًا. أضف الحقول الجديدة بدل استمرار القراءة من استجابة تسجيل السائق القديمة التي لا تغطي الشاشة التشغيلية.

## 4. الوثائق وحالاتها

كل عنصر في `documents` يحتوي على:

```text
documentId: string
documentType: string
documentTitle: string
status: string
statusText: string
verificationStatus: string?
expiryDate: string?          // YYYY-MM-DD، تاريخ فقط
daysUntilExpiry: int?
requiresRenewal: bool
```

- اعرض `documentTitle` و`statusText` كما أعادهما الباك باللغة المطلوبة.
- اختر اللون أو الأيقونة باستخدام `status`، وليس بمقارنة النص العربي أو الإنجليزي.
- `Expired`: منتهية الصلاحية؛ لون تحذير أحمر.
- `ExpiringSoon`: تنتهي خلال 30 يومًا شاملة اليوم؛ لون تحذير برتقالي.
- `Approved`: معتمدة؛ لون أخضر. وجودها لا يضمن وجود تاريخ انتهاء إذا كانت الوثيقة بلا تاريخ مخزّن.
- `Submitted`, `UnderReview`: حالة انتظار المراجعة.
- `Rejected`, `NeedsChanges`, `ResubmissionRequired`: تحتاج إجراء أو مراجعة وفق الحالة.
- `Draft`, `Unreviewed`: غير معتمدة بعد.
- أي كود غير معروف: اعرض النص القادم من الباك بتنسيق محايد حتى لا يتعطل التطبيق عند إضافة حالات جديدة.

`verificationStatus` تحفظ حالة مراجعة الوثيقة الأصلية، بينما `status` قد تكون `Expired` أو `ExpiringSoon` بسبب تاريخ الصلاحية. لا تستبدل تحذير انتهاء الصلاحية بعلامة Approved لمجرد أن آخر مراجعة كانت معتمدة.

`expiryDate` تاريخ فقط؛ لا تحوّله من UTC إلى توقيت محلي بما قد يغيّر اليوم. `daysUntilExpiry` محسوب في الباك وفق تاريخ UTC الحالي؛ استخدمه كما ورد، ولا تعِد حسابه بساعة الجهاز. عند غياب تاريخ الانتهاء لا تعرض تاريخًا أو عدد أيام افتراضيًا.

لا تجمع `DrivingLicenseFront` و`DrivingLicenseBack` أو وثائق الهوية الأمامية والخلفية على أنها نفس نوع الوثيقة دون قرار واضح في تصميم التطبيق؛ الاستجابة قد تعيدها عناصر منفصلة. الباك يعيد أحدث رفع لكل نوع، وليس سجل التجديدات بالكامل.

نوع `HealthCertificate` المرسوم في وصف الشاشة غير مدعوم كنوع مستقل في enum الباك الحالي. لا تعرض شهادة صحية تجريبية أو تفترض أن هناك endpoint يدعم رفعها.

## 5. تفاصيل تذكرة الدعم

استخدم الحقول التالية عند وجود `latestSupportTicket`:

```text
ticketId: string
subject: string
body: string
status: string
priority: string
createdAtUtc: DateTime
updatedAtUtc: DateTime?
```

اعرض العنوان والوصف والحالة والأولوية والتاريخ الفعلي. محتوى `subject` و`body` كتبه المستخدم، ويظل بلغته الأصلية؛ الـ header لا يترجم النص الحر. لا تفترض وجود `statusText` أو `priorityText` لهذا الكائن؛ تسميات الحالات المعروفة يمكن ترجمتها بقاموس التطبيق، والحالات غير المعروفة تُعرض بقيمتها الأصلية. لا تفترض مسار API لتفاصيل التذكرة أو تعديلها اعتمادًا على هذا الاستعلام وحده.

## 6. التحميل والتحديث والصورة

- أظهر loading أثناء أول طلب، ثم اعرض محتوى الاستجابة أو خطأ قابلًا لإعادة المحاولة.
- أعد الجلب عند فتح الشاشة، والسحب للتحديث، وتغيير لغة التطبيق. أعد الجلب بعد نجاح إجراء فعلي يغيّر الوثائق أو الملف أو حالة الوردية.
- عند العودة للشاشة بعد فترة، حدّث البيانات قبل الاعتماد على حالة Online والصورة القديمة.
- `profileImageUrl` رابط قراءة صالح لمدة 15 دقيقة. إذا انتهت صلاحيته، أعد جلب الملف للحصول على رابط جديد؛ لا تبنِ رابط CDN من `profileImageStorageKey` ولا تدخل في حلقة إعادة طلب غير محدودة.
- إذا استُخدم cache، افصله حسب المستخدم واللغة، وأبطله عند تغيير الحساب أو تسجيل الخروج. لا تعرض حالة مخزّنة على أنها حالة اتصال لحظية مؤكدة.
- لا تسمح باستجابة طلب لغة قديمة أن تستبدل بيانات آخر لغة اختارها المستخدم؛ ألغِ الطلب السابق أو تجاهل نتائجه عند تغيّر اللغة.

## 7. الأزرار والإجراءات غير المدعومة

المنفّذ ضمن هذا التعديل هو **استعلام الشاشة**. لا تفترض وجود العمليات التالية لمجرد ظهور أزرارها في الرسم:

- `POST /api/v1/driver/profile/documents` غير منفّذ حاليًا بهذا المسار.
- لا يوجد في هذا العقد مسار لطلب تغيير المركبة أو تعديل الملف أو تغيير الرتبة.
- `requiresRenewal` إشارة لحاجة الوثيقة للتجديد، وليست دليلًا على توفر عملية رفع.

أخفِ الأزرار التي ليس لها تكامل فعلي، أو اجعلها غير مفعّلة مع توضيح مترجم. لا تعرض رسالة نجاح لرفع أو تعديل لم ينفّذه الباك. إذا كان مشروع الموبايل يملك مسار رفع وربط معتمدًا بالفعل، تحقّق من عقده وصلاحياته قبل استخدامه؛ لا يُستنتج مساره من هذه الوثيقة.

صلاحية بدء الوردية قرار يراجعه الباك في مسار بدء العمل؛ بيانات شاشة الملف لا تُستخدم لتجاوز هذا الفحص.

## 8. الأخطاء

| HTTP | تعامل الموبايل |
|---|---|
| `401` | استخدم تدفق تحديث التوكن أو إعادة تسجيل الدخول المعتمد في التطبيق. |
| `403` | اعرض خطأ صلاحية؛ هذا المسار يتطلب دور Driver. |
| `404` | اعرض أن ملف السائق غير موجود أو غير مرتبط بالحساب، دون إنشاء ملف محلي أو استخدام بيانات سائق آخر. |
| خطأ شبكة أو `5xx` | اعرض إعادة المحاولة، مع توضيح أن أي بيانات مخزّنة ليست تحديثًا ناجحًا. |

## 9. قائمة قبول التعديل

- [ ] الشاشة تجلب بياناتها من `GET /api/v1/driver/profile` بتوكن السائق، دون `driverId`.
- [ ] العربية والإنجليزية تعملان بتغيير الـ header، وتغيير اللغة يعيد جلب البيانات.
- [ ] الاسم والوصف والحالات وعناوين الوثائق تأتي من الباك؛ تسميات الواجهة العامة من ترجمة التطبيق.
- [ ] لا توجد قيم ثابتة للتقييم أو الطلبات أو نسبة القبول أو تاريخ الانضمام أو المركبة أو التذكرة.
- [ ] غياب التقييم يختلف بصريًا عن تقييم صفر، وعدد المراجعات والطلبات `0` يظهر بشكل صحيح.
- [ ] نسبة القبول والرتبة ومحافظة اللوحة عند `null` لا تظهر كبيانات حقيقية.
- [ ] بيانات المركبة الناقصة لا تسبب crash، ولا يظهر اعتماد أسطول مستقل اعتمادًا على مراجعة الوثيقة.
- [ ] الوثائق المنتهية والقريبة من الانتهاء تستخدم حالة الباك، والقائمة الفارغة تعرض حالة فارغة.
- [ ] غياب الفرع أو المطعم أو تذكرة الدعم لا يسبب crash ولا ينتج محتوى افتراضيًا.
- [ ] رابط الصورة المنتهي أو الفاشل يُعالج بأيقونة عامة وتجديد الطلب دون تخمين رابط تخزين.
- [ ] حالات `401`, `403`, `404` وخطأ الشبكة لها عرض وإجراء مناسب.
- [ ] أزرار التجديد وتغيير المركبة لا تعرض نجاحًا دون endpoint فعلي.
