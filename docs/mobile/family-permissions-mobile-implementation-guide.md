# دليل الموبايل التفصيلي لصلاحيات أفراد العائلة

هذا الملف يشرح للموبايل كيف يقرأ صلاحيات العائلة ويعرضها، وما الإجراء الذي تسمح به كل صلاحية. كتالوج المدير يحتوي 17 صلاحية. الباك إند هو مصدر القرار النهائي؛ إخفاء زر في التطبيق يحسّن الواجهة، لكنه لا يحل محل التحقق من الصلاحية على الخادم.

## 1. المسارات التي يستخدمها التطبيق

أرسل `Authorization: Bearer <customer access token>` مع كل طلب.

| الغرض | المسار |
| --- | --- |
| تحميل سياق الحساب الحالي وصلاحيات العضو الفعلية | `GET /api/v1/customer/family/me` |
| تحميل صلاحيات عضو لإدارة المدير | `GET /api/v1/customer/family/members/{memberId}/permissions` |
| حفظ تغيير صلاحيات عضو | `PUT /api/v1/customer/family/members/{memberId}/permissions` |
| فحص القرارات الفعلية للعضو المحدد | `GET /api/v1/customer/family/members/{memberId}/capabilities` |

العضو يستخدم `GET /family/me`؛ كل سياق عضو فيه `memberId` و`memberSubscriptionId` و`capabilities`. المدير يستخدم مسار `permissions` لعرض إعدادات العضو وتعديلها. `capabilities` قرارات فعالة لمستخدم حالي وعضو محدد، أما `permissions` فهي إعدادات العضو التي يراها المدير. لا تخلط بين الاثنين.

لا تعتمد على `roles` أو `permissions` العامة في استجابة تسجيل الدخول لتحديد صلاحيات العائلة. استخدم سياق `/family/me`، ولا تعرض شاشة اختيار دور تسمح للمستخدم باكتساب صلاحيات.

### قرار إظهار الإجراء

- إذا كان المستخدم عضوًا، اقرأ `capabilities` من سياق `/family/me`، وابحث عن `action` المطلوب. اعرض الإجراء فقط عندما تكون `allowed: true`، مع مراعاة حالة اليوم أو الاشتراك.
- إذا كان المستخدم مديرًا، اقرأ كتالوج صلاحيات العضو من `/permissions`. اعرض قيمة `value` في مفتاح التحكم، ولا تسمح بالتبديل إذا كانت `isManagerConfigurable: false`.
- في أي إجراء كتابة، نفّذ الطلب على الخادم وتعامل مع `403` أو `409` كقرار نهائي. حدّث البيانات بعد تغيير الصلاحيات أو انتهاء الحساب/إيقاف الوصول.
- `requiredPermission` و`reasonCode` من `/capabilities` مفيدان لتفسير المنع. لا تحوّل أي قيمة غير معروفة إلى سماح.
- لا تستخدم `canEditDailyMeals` وحده لإظهار كل أزرار التقويم؛ فهو مؤشر عام. الإضافة والتبديل والتأكيد واختيار المطعم إجراءات مختلفة.

مثال لقرار فعلي:

```json
{
  "action": "UnitExchange",
  "allowed": true,
  "reasonCode": null,
  "requiredPermission": "UnitExchange"
}
```

تظهر خاصية `capabilities` داخل كل سياق في `/family/me` بالشكل نفسه. أما المدير فيستطيع قراءة القرارات للعضو المحدد من مسار `/{memberId}/capabilities`.

## 2. عرض اسم الصلاحية وشرحها

كل عنصر في `groups[].permissions[]` من `/permissions` يحتوي على:

| الحقل | الاستخدام |
| --- | --- |
| `key` | المعرّف الثابت للصلاحية؛ استخدمه للربط البرمجي، ولا تترجمه. |
| `labelAr` / `labelEn` | اسم الصلاحية بالعربية والإنجليزية. |
| `descriptionAr` / `descriptionEn` | شرح ما تسمح به الصلاحية باللغة نفسها. اعرضه أسفل الاسم. |
| `value` | حالة الصلاحية الحالية عند العضو. |
| `isSupported` | هل الإجراء متاح في المنتج. |
| `isManagerConfigurable` | هل يستطيع المدير تغييرها. |
| `requiredPermissions` | مفاتيح القراءة التي يضمّنها الباك تلقائيًا عند منح هذه الصلاحية. |

اختَر الاسم والشرح من زوج اللغة المطابق للغة التطبيق النشطة، وغيّرهما فور تبديل اللغة دون إعادة تشغيل. إذا كان أحد النصين فارغًا بسبب إصدار قديم، استخدم النص المقابل من اللغة الأخرى. لا تنشئ قاموسًا ثانيًا داخل Flutter؛ نصوص الشرح تأتي من الباك إند.

```dart
final label = isArabic ? item.labelAr : item.labelEn;
final description = isArabic ? item.descriptionAr : item.descriptionEn;
```

في شاشة المدير، اعرض صلاحية غير قابلة للتعديل كحالة ثابتة مع شرحها، ولا تعرضها كمفتاح يمكن تغييره. أخفِ العناصر التي `isSupported` فيها `false`. الصلاحيتان `changeProgram` و`changeDeliveryTime` غير موجودتين في كتالوج المدير الحالي؛ لا تعرضهما من خصائص DTO قديمة.

## 3. شرح الصلاحيات الـ17 وسلوك الشاشة

أسماء المفاتيح في الجدول مطابقة لقيم `key` في JSON. الشروح الثنائية المتاحة للتطبيق هي `descriptionAr` و`descriptionEn` في الاستجابة.

| المجموعة | المفتاح | ما الذي تسمح به؟ | سلوك واجهة الموبايل |
| --- | --- | --- | --- |
| الوجبات | `viewCalendar` | قراءة تقويم اشتراك العضو، أيام الخدمة، الوجبات المختارة وحالة اليوم. | أظهر تقويم هذا الاشتراك للقراءة. لا تعرض أزرار التعديل اعتمادًا على هذه الصلاحية وحدها. |
| الوجبات | `viewFamilyCalendars` | قراءة تقاويم أفراد العائلة الآخرين. | اسمح بفتح تقويم الأخ/الفرد الآخر فقط إذا أجاز الخادم الوصول إليه؛ لا تجعلها صلاحية تعديل. |
| الوجبات | `selectRestaurant` | اختيار مطعم متاح ليوم الخدمة. | أظهر اختيار المطعم عندما يكون اليوم قابلًا للتعديل. لا تعتبرها سماحًا بإضافة وجبات أو تأكيدها. |
| الوجبات | `editDailyMeals` | صلاحية التعديل القديمة الواسعة؛ تسمح بإضافة الوجبات وتبديلها واستخدام الاختيار التلقائي. | عند وجودها، قدّم سلوك التعديل القديم كاملًا. في الإعدادات الجديدة استخدم `editMealsAndDays` و`unitExchange` للتحكم الأدق. |
| الوجبات | `confirmMeals` | تأكيد يوم مكتمل وإرسال اختياراته إلى المطعم. | أظهر زر التأكيد عند اكتمال اليوم وقبول الخادم. لا تسمح هذه الصلاحية بتغيير الوجبات. |
| الوجبات | `editMealsAndDays` | إضافة وجبة إلى خانة متاحة وتجهيز وجبات اليوم. يمكن للعضو إضافة وجبة أو ملء اليوم. لا تسمح وحدها باستبدال وجبة موجودة. | أظهر إضافة الوجبة للخانة الفارغة. لا تعرض الاستبدال بسبب هذه الصلاحية وحدها. إكمال اليوم لا يساوي تأكيده للمطعم. |
| الوجبات | `unitExchange` | استبدال وجبة مختارة بوجبة أخرى حين يكون اليوم مفتوحًا وقابلًا للتعديل. | أظهر الاستبدال لوجبة موجودة فقط؛ لا تسمح بإضافة وجبة لخانة فارغة. تاريخ الإغلاق وحالة اليوم يظلان شرطًا. |
| البرنامج والاشتراك | `viewProgram` | قراءة برنامج العضو وبيانات اشتراكه. هذه صلاحية أساسية مفعّلة دائمًا. | أظهر خطة واشتراك العضو نفسه. العنصر ثابت في شاشة المدير وليس مفتاحًا قابلًا للإيقاف. |
| البرنامج والاشتراك | `viewFamilyPlans` | قراءة برامج وخطط أفراد العائلة الآخرين. | اسمح بفتح خطة فرد آخر فقط عندما يسمح قرار الخادم بذلك؛ لا تستنتج صلاحية تعديل الخطة. |
| البرنامج والاشتراك | `requestFreeze` | بدء إجراء طلب تجميد اشتراك العضو وفق سياسة التجميد. | أظهر إجراء طلب التجميد، ثم اعرض نتيجة الخادم أو متطلبات الطلب. الصلاحية لا تتجاوز قيود الاشتراك والسياسة. |
| البرنامج والاشتراك | `requestRenewal` | بدء إجراء تجديد اشتراك العضو. | أظهر بدء التجديد؛ أكمل خطوات الخطة والدفع أو التأكيد التي يطلبها الفلو. لا تعرضه كتجديد تلقائي. |
| البرنامج والاشتراك | `requestUpgrade` | بدء طلب ترقية اشتراك العضو. | أظهر خيارات الترقية عند السماح، ثم اتبع نتيجة التسعير والدفع؛ لا تغيّر الخطة محليًا قبل تأكيد الخادم. |
| البرنامج والاشتراك | `cancelSubscription` | بدء إجراء إلغاء اشتراك العضو. | اعرض عرض الإلغاء/التأكيد الذي يرجعه الخادم، وتعامل مع التعارضات ومتطلبات التسوية. لا تنفّذ الإلغاء محليًا. |
| التوصيل | `editAddress` | تعديل عنوان توصيل اشتراك العضو. | أظهر تعديل العنوان فقط. لا تخلطها بتغيير وقت التوصيل؛ ذلك الخيار غير موجود في الكتالوج. |
| الحساب والفواتير | `changePassword` | تغيير كلمة مرور حساب العضو. صلاحية حساب أساسية مفعّلة دائمًا. | أظهر تغيير كلمة مرور الحساب الحالي. العنصر ثابت في شاشة المدير وليس مفتاحًا قابلًا للإيقاف. |
| الحساب والفواتير | `viewInvoices` | قراءة فواتير اشتراك العضو نفسه. | أظهر فواتير المستخدم/اشتراكه فقط وفق نتائج الخادم. هذه الصلاحية لا تفتح فواتير بقية العائلة. |
| الحساب والفواتير | `viewFamilyInvoices` | قراءة فواتير أفراد العائلة. | أظهر مساحة فواتير العائلة فقط عندما يسمح الخادم؛ لا تستنتجها من `viewInvoices`. |

### فرق نطاق بيانات العضو عن بيانات العائلة

`viewCalendar`, `viewProgram`, `viewInvoices` تتعلق ببيانات العضو/اشتراكه الشخصي. أما `viewFamilyCalendars`, `viewFamilyPlans`, `viewFamilyInvoices` فهي صلاحيات نطاق عائلي منفصلة. العضو لا يحصل على بيانات الإخوة تلقائيًا لمجرد امتلاكه صلاحية على بياناته. استخدم `memberId` و`memberSubscriptionId` اللذين أعادهما السياق الحالي، ولا تستبدل معرّف الاشتراك بمعرّف العضو.

## 4. تعديل صلاحيات عضو من شاشة المدير

1. حمّل `GET /api/v1/customer/family/members/{memberId}/permissions` عند فتح شاشة الصلاحيات.
2. اعرض المجموعات التي أعادها الخادم، ثم لكل صلاحية الاسم والشرح والحالة. لا تثبّت عدد العناصر أو ترتيبها في Flutter.
3. أرسل المفاتيح التي تغيّرت فقط مع `expectedVersion`. الحقول غير المرسلة تبقى كما هي. لا ترسل `groups` كبديل عن الحقول.
4. استخدم القيم المشتقة التي يعيدها الباك إند. منح صلاحية كتابة للتقويم يضمن وجود متطلبات القراءة اللازمة، ومنها `viewCalendar` و`viewProgram` وفق العقد.
5. اعرض الاستجابة المحفوظة بعد نجاح `PUT`. إذا رجع `409 family.permissions_changed`، أعد تحميل الصلاحيات واطلب من المدير إعادة التغيير؛ لا تعِد إرسال نسخة قديمة فوق تعديل جلسة أخرى.

مثال لتفعيل إضافة الوجبات وتبديلها، دون منح التعديل القديم الواسع:

```http
PUT /api/v1/customer/family/members/{memberId}/permissions
Content-Type: application/json
```

```json
{
  "expectedVersion": 4,
  "editMealsAndDays": true,
  "unitExchange": true
}
```

## 5. المسارات التشغيلية المرتبطة

استخدم `memberSubscriptionId` من سياق `/family/me`، وتاريخ خدمة بصيغة `yyyy-MM-dd` في مسارات التقويم.

| الإجراء | المسار |
| --- | --- |
| عرض التقويم | `GET /api/v1/customer/subscriptions/{subscriptionId}/calendar` |
| عرض يوم | `GET /api/v1/customer/subscriptions/{subscriptionId}/days/{date}` |
| قائمة المطاعم ليوم | `GET /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/restaurants` |
| وجبات مطعم وخانة | `GET /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/restaurants/{restaurantId}/meals?slot={slot}` |
| اختيار مطعم | `POST /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/restaurant` |
| إضافة/استبدال وجبة في خانة | `POST /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/meals/slot` |
| إكمال اختيارات اليوم | `POST /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/complete` |
| تأكيد وإرسال اليوم | `POST /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/confirm` |
| الاختيار التلقائي القديم | `POST /api/v1/customer/subscriptions/{subscriptionId}/days/{date}/auto-select`؛ يتطلب `editDailyMeals` |
| عنوان الاشتراك | `GET` أو `PUT /api/v1/customer/subscriptions/{subscriptionId}/delivery-address` |
| فواتير الاشتراك | `GET /api/v1/customer/subscriptions/{subscriptionId}/invoices` |
| طلب تجميد | `POST /api/v1/customer/subscriptions/{subscriptionId}/freeze-requests` |
| طلب ترقية | `POST /api/v1/customer/subscriptions/{subscriptionId}/upgrade-requests` |
| طلب تجديد | `POST /api/v1/customer/subscriptions/{subscriptionId}/renewal-requests` |
| معاينة الإلغاء | `GET /api/v1/customer/subscriptions/{subscriptionId}/cancellation-quote` |
| تنفيذ طلب الإلغاء | `POST /api/v1/customer/subscriptions/{subscriptionId}/cancellation-requests` |
| كل فواتير العميل المصرّح بها | `GET /api/v1/customer/invoices` |
| كلمة المرور | `PUT /api/v1/customers/me/password`؛ لا تربط تغيير كلمة المرور بفصل العضو عن العائلة. |

قد تختلف أهلية الإجراء حسب حالة الاشتراك أو اليوم، حتى لو كانت الصلاحية ممنوحة. استجابة التقويم وقرار capabilities يحددان ما يمكن عرضه، والـ API يتحقق مرة أخرى عند التنفيذ.

## 6. حالات تحقق مطلوبة في تطبيق الموبايل

- **إضافة فقط:** `EditMealsAndDays=true` و`UnitExchange=false`: يستطيع العضو إضافة وجبات لخانات متاحة وإكمال اليوم، ولا يستطيع استبدال وجبة موجودة أو تأكيدها دون `ConfirmMeals`.
- **تبديل فقط:** `UnitExchange=true` و`EditMealsAndDays=false`: يستطيع استبدال وجبة في يوم مفتوح، ولا يستطيع ملء خانة فارغة.
- **تأكيد فقط:** `ConfirmMeals=true` دون تعديل: يستطيع تأكيد يوم مكتمل فقط.
- **مطعم فقط:** `SelectRestaurant=true` دون صلاحيات تحرير الوجبات: يستطيع اختيار مطعم ولا يستطيع اختيار وجبات.
- **القراءة فقط:** `ViewCalendar=true`: يستطيع فتح تقويمه ولا يرى أزرار الكتابة غير الممنوحة.
- **نطاق الإخوة:** فعّل واحدة من صلاحيات النطاق العائلي فقط، وتأكد أنها لا تكشف بقية بيانات العائلة خارج نطاقها.
- **يوم مغلق أو اشتراك غير مؤهل:** أخفِ أو عطّل الإجراء عند ظهور المنع في البيانات، وتوقع أن يرفضه الخادم إذا تغيّرت الحالة بين القراءة والتنفيذ.
- **تبديل اللغة:** افتح شاشة الصلاحيات بالعربية، بدّل إلى الإنجليزية وهي مفتوحة، ثم ارجع للعربية. يجب أن يتبدل الاسم والشرح معًا من قيم الـ API دون إعادة تشغيل.
- **استجابة قديمة أو عنصر جديد:** لا تفترض أن عدد الصلاحيات ثابت؛ اعرض المفاتيح المدعومة التي أعادها الخادم فقط، مع تعامل آمن مع مفاتيح مستقبلية.
