# مواصفة أزرار عضو العيلة للموبايل

يوجد إجراءان مختلفان تمامًا ويجب أن يظهر كل إجراء في زر مستقل.

## الزر الأول: إنشاء دخول للعضو

النص الظاهر:

```text
إنشاء كلمة مرور للعضو
```

الغرض: إنشاء بيانات دخول خاصة للعضو مع بقائه داخل العيلة وتحت إدارة المدير.

الطلب:

```http
PUT /api/v1/customer/family/members/{memberId}/access
```

```json
{
  "hasSeparateAccount": true,
  "generateTemporaryPassword": true,
  "credentialOperationKey": "uuid-new-per-operation"
}
```

بعد النجاح:

- اعرض `generatedPassword` للمدير مرة واحدة مع زر نسخ ومشاركة.
- اعرض الحالة: `داخل العيلة وتحت إدارة المدير`.
- يجب أن تكون `detachedFromFamilyManagement = false`.
- لا تخزن كلمة المرور أو تعرضها من الذاكرة بعد إغلاق النافذة.
- إذا رجع `passwordAlreadyIssued = true` اعرض إصدار كلمة جديدة بمفتاح جديد.

## دخول العضو

العضو يستخدم نفس صفحة الدخول العادية:

```http
POST /api/v1/auth/customers/login
```

يمر بالتسلسل:

```text
كلمة مؤقتة → رمز التحقق → كلمة مرور جديدة → دخول التطبيق
```

بعد الدخول اعرض فقط ما تسمح به `permissions`، مثل التقويم والاشتراك والوجبات.

## الزر الثاني: فصل العضو عن العيلة

النص الظاهر:

```text
فصل العضو عن العيلة
```

الغرض: إيقاف إدارة المدير للعضو. هذا الإجراء مستقل عن إنشاء كلمة المرور.

الطلب:

```http
POST /api/v1/customer/family/members/{memberId}/detach
```

بعد النجاح:

- تصبح `detachedFromFamilyManagement = true`.
- أزل العضو من قائمة إدارة العيلة.
- لا تحذف اشتراك العضو أو تقويمه.
- لا تعرض للمدير صلاحيات التحكم الخاصة به بعد الفصل.

## قواعد عرض الأزرار

| الحالة | إنشاء كلمة مرور | فصل العضو |
|---|---:|---:|
| داخل العيلة ولا يوجد دخول | يظهر | مخفي أو معطل |
| داخل العيلة وله دخول فعال | إصدار كلمة جديدة | يظهر |
| يحتاج تغيير كلمة المرور | إصدار كلمة جديدة | معطل |
| مفصول | مخفي | مخفي |

لا تستخدم اسم «حساب مستقل» في الواجهة؛ الاسم المقصود هو «دخول خاص للعضو». لا تجعل زر إنشاء الدخول يغير حالة الفصل.
