## التقويم والصلاحيات

- [ ] effective calendar subscription ID = current ثم upcoming، والـ path لا يستخدم memberId.
- [ ] تغيير العضو أو اليوم أو البحث يتجاهل الردود المتأخرة؛ mutation لا يكتب على شاشة تغير سياقها.
- [ ] للمستخدم العضو المربوط، `family.access_paused` و`family.access_disabled` و`family.permission_required` تمنع فعله؛ المدير يظل قادراً على إدارة عضو مستهدف موقوف. `family.action_not_available` يمنع الفعل غير المدعوم لكل الأدوار؛ cutoff يحدده API.
- [ ] لا fixed 72-hour cutoff؛ لا يعاد حساب سياسة القفل بالهاتف.
- [ ] اختيار slot يلتزم بالعدد من API وبسلوك الاستبدال الخادمي؛ لا remove endpoint مخترع.
- [ ] confirm (تأكيد العميل) منفصل عن complete (إتمام الصندوق)؛ لا افتراض إجباري أو ديمومة لـ Idempotency-Key؛ النجاح يتبعه GET اليوم والتقويم.
- [ ] صلاحيات PUT تحوي الثمانية المطلوبة و`expectedVersion`؛ unsupported capabilities لا تظهر كأنها قابلة للتمكين؛ تعارض النسخة يعرض أحدث البيانات ولا يكتب فوقها آلياً.

## التعريب والتنسيق

- [ ] copy عربي وإنجليزي لكل عناصر الواجهة والحالات والوصولية، وتبديل `ar → en → ar` بلا reload مع RTL/LTR.
- [ ] `Accept-Language` يرسل مع الطلبات؛ labels الترجمة لا تعدل enum أو slot أو key أو error code.
- [ ] أسماء domain ثنائية اللغة تختار active locale ثم الحقل البديل ثم label مترجم.
- [ ] Asia/Kuwait كتوقيت أعمال؛ KWD بثلاث منازل عشرية. لا أسعار/أيام مصطنعة.

## أدلة اختبارات إصدار الخادم

تم توثيق نتائج release checkout المسجل عند commit المذكور: 234 اختبار unit و1 اختبار PostgreSQL/HTTP بتغذية اختبارية ممولة ومزود دفع مزدوج. هذه نتائج backend وليست تشغيل Flutter. لا يوجد دفع live أو قبول جهاز/RTL في هذه المراجعة. توجد ثلاث نتائج integration سابقة في سياق منفصل؛ لا تنسبها إلى commit/checkout الحالي. يجب اختبار التطبيق باللغتين وحالات الشبكة قبل الإطلاق.

## ما تحقق عند كتابة هذه الوثائق

راجعت ملفات DTOs/controllers/handlers من checkout المصدر عند commit المذكور. لم أشغل Flutter أو جهازاً فعلياً أو عملية دفع live. أي اعتماد release على هذه المستندات يجب أن يكمل اختبارات التطبيق باللغتين وحالات الشبكة في بيئة الاختبار؛ القائمة أعلاه ليست ادعاء تنفيذ تلك الاختبارات.
