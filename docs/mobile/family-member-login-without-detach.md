# دخول عضو العيلة مع بقاء الإدارة

هذا الفلو ينشئ للعضو بيانات دخول خاصة به، مع بقائه داخل العيلة وتحت إدارة المدير. إنشاء كلمة المرور لا يعني فصل العضو.

## من لوحة المدير

استدعِ:

```http
PUT /api/v1/customer/family/members/{memberId}/access
```

```json
{
  "hasSeparateAccount": true,
  "generateTemporaryPassword": true,
  "credentialOperationKey": "uuid-unique-per-operation"
}
```

اعرض `generatedPassword` للمدير مرة واحدة فقط. لا تخزنها في الهاتف أو السجلات.

هذه العملية لا تستدعي endpoint الفصل ولا تغيّر `detachedFromFamilyManagement`.

## دخول العضو

العضو يستخدم نفس شاشة الدخول العادية:

```http
POST /api/v1/auth/customers/login
```

يرسل رقم الهاتف وكلمة المرور المؤقتة. عند أول دخول يتبع `nextStep` الذي يرجعه السيرفر، ثم يثبت كلمة مرور جديدة بعد التحقق.

## الصلاحيات

بعد نجاح الدخول، اعتمد على `roles` و`permissions` من استجابة الدخول ومن بيانات الحساب. اعرض للعضو فقط الصفحات والعمليات المسموحة له، مع إبقاء الاشتراك والتقويم مرتبطين بالعيلة.

## ممنوعات مهمة

- لا تستخدم زر إنشاء كلمة المرور لتنفيذ فصل العضو.
- لا ترسل `hasSeparateAccount: false` عند إعادة المحاولة.
- لا تستخدم `DetachedFromFamilyManagement` لتحديد وجود حساب دخول.
- لا تحفظ كلمة المرور المؤقتة أو رمز التحقق في التخزين المحلي.
- الفصل يتم فقط من إجراء مستقل للمدير، وبعده يفقد العضو تحكم المدير مع بقاء اشتراكه حسب قواعد الباك إند.

## حالات الواجهة

- `generatedPassword`: اعرض نافذة نسخ ومشاركة للمدير.
- `passwordAlreadyIssued`: اعرض إصدار كلمة جديدة بدل محاولة قراءة القديمة.
- `nextStep = family_verify_otp`: افتح شاشة رمز التحقق.
- `nextStep = family_set_password`: افتح شاشة كلمة المرور الجديدة.
- `detachedFromFamilyManagement = false`: اعرض أن العضو ما زال تحت إدارة العيلة.
